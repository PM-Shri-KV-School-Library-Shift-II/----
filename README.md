## Overview

The site presents the library's digital collection, reading campaigns and student resources as a set of static pages that work without a backend.

It contains 25 HTML pages covering:

| Area | Pages |
| --- | --- |
| Home | Landing page with hero, explore, events, features and contact sections |
| Collections | Websites, Study Materials, Digital Libraries, Resources and Books, Biography, Multimedia |
| Curriculum | Support Material, NCF Split-up, Career Cards, Educational Portals |
| Campaigns | Book Exhibition, Hindi Pustak Pradarshini, Hindi Books Exhibition, Hindi Pakhwada, Reading Promotion Week, Digital Book Review, World Book Day |
| Media | Activity videos and photo galleries |
| Tools | Quiz Portal, DocuMind AI, Email Contact |

---

## Features

- Fully static, works offline once cached, and requires no account or backend.
- Responsive layout with a mobile navigation drawer and a sticky notification bar.
- Skip links, visible focus states and landmark regions for keyboard and screen-reader users.
- Content Security Policy delivered through a meta element on every page, with Subresource Integrity on all externally hosted scripts and styles.
- Automatic footer year and typing animation on the landing page.
- Client-side quiz with instant scoring.
- PDF viewer and AI-assisted reading tool (see [DocuMind AI](#documind-ai)).

## Getting Started

### Prerequisites

- Node.js 18 or newer
- npm (bundled with Node.js)
- Google Chrome or Chromium, only if you want to run the smoke test

### Installation

```bash
git clone https://github.com/PM-Shri-KV-School-Library-Shift-II/----.git
cd ----
npm install
```

`node_modules/` is generated by `npm install` and is not tracked by git.

To view the site, open `index.html` in a browser or serve the directory locally:

```bash
npx serve .
```

## Scripts

| Command | Purpose |
| --- | --- |
| `npm run check` | Static health check: inline scripts, CSP, Subresource Integrity, internal links, accessibility hooks, JavaScript syntax and mojibake detection |
| `npm run build` | Minify all site scripts into `assets/js/bundle.min.js` and `assets/css/style.min.css` |
| `npm run build:js` | JavaScript minification only |
| `npm run build:css` | CSS minification only |
| `npm run smoke` | Load every page in headless Chrome and report console errors, page errors and failed requests |
| `npm run audit` | Run `npm audit` and fail on high-severity advisories |
| `npm test` | Run `check` followed by `smoke` |

The smoke test looks for a Chrome or Chromium installation in the usual locations. To use a specific binary, set `CHROME_PATH`. If no browser is found the test reports that it was skipped rather than failing the build.

After editing any file under `assets/js/` or `assets/css/`, run `npm run build` before committing, because the minified files are what the pages load.

## Security

The site is static, so there are no server secrets, database credentials or authentication to leak. The following measures are in place:

- **Content Security Policy** set through a meta element on every page, restricting `default-src`, `script-src`, `style-src`, `img-src`, `frame-src` and `object-src`.
- **Subresource Integrity** hashes on every third-party script and stylesheet.
- **DOMPurify 3.4.16** sanitises any HTML produced from PDF text or model output before it reaches the DOM.
- **pdf.js** is configured with `isEvalSupported: false` so font and CMap parsing never evaluates generated code.
- **No stored API keys.** DocuMind AI keys are supplied by the visitor at runtime and remain in that visitor's browser storage.
- **Dependency audit** reports zero vulnerabilities.

Because GitHub Pages does not expose custom response headers, protections that would normally be sent as headers, such as `X-Frame-Options` and `frame-ancestors`, are delivered through the meta CSP where the specification allows it.

## Accessibility

The pages were audited against WCAG 2.1 level AA:

- Skip links and `tabindex="-1"` main landmarks so keyboard users can bypass repeated navigation.
- Focus is moved after skip-link activation and after scripted in-page navigation.
- Text colour contrast of at least 4.5:1 for body text and 3:1 for large text and interface graphics.
- Descriptive `alt` text on images, `aria-hidden` on decorative icons, and labelled form controls.
- `prefers-reduced-motion` handling for animations.
- Single `id` value per page and no inline event handlers, which keeps the CSP strict.

## DocuMind AI

`PDF-Ai/` contains DocuMind AI, an in-browser tool for reading and annotating PDF documents.

- Documents are parsed locally with pdf.js; they are never uploaded to this project's servers, because there are none.
- Summaries, explanations and quiz generation are requested from OpenRouter. This requires a visitor's own OpenRouter API key, entered under Settings and stored in that visitor's `localStorage`.
- The key is sent only to `https://openrouter.ai`, which is allowlisted in the page's `connect-src` directive. It is never committed to this repository.
- Extracted and generated markup is sanitised with DOMPurify, and TeX input is rendered with `trust` disabled.

## Deployment

The site is published with GitHub Pages from the `main` branch.

1. Push to `main`.
2. In the repository settings, open **Pages** and set the source to `main` / root.
3. The site is served at `https://pm-shri-kv-school-library-shift-ii.github.io/----/`.

No build step runs during deployment. Run `npm run build` locally first so that the committed minified assets match the source files.

`sitemap.xml` and `google6eca1236c00edbff.html` are published for search-engine indexing and verification.
